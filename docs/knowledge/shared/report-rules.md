# 报表共享统计规则

作用域：本项目报表统计；filters 和参与度分母的例外见模块地图。以下为需求与已读取实现相互支持的口径，不推广至其他项目。

## 统一字段术语

本表仅记录容易混淆或物理字段名不能直观表达业务含义的术语。规则正文直接使用业务称呼；普通字段不重复登记，完整字段说明见[数据库说明](database.md)。不改变计算口径。同一术语可对应不同表中的关联字段；名称相同不代表DDL保证唯一。任务编号不是执行链路标识，推荐客户、点击客户和接触客户标识保留角色差异。

| 统一术语 | 字段 | 含义与注意事项 |
| --- | --- | --- |
| 排程执行日期 | `swe_plan_sence_cron.execute_day` | 规划中的技能安排执行的日期，不代表实际已经执行。 |
| 技能编号 | `swe_wealth_plan_scenes.scene_id`，`swe_cron_result_index.skill_id` | 规划场景或执行结果引用的技能业务编号，对应技能目录的skill_id；不是场景明细表的自增主键id。 |
| 实际执行时间 | `swe_cron_executions.actual_time` | 某次任务实际开始执行的时间；同一任务同一日期可能有多次执行记录。 |
| 执行链路标识 | `swe_cron_executions.trace_id`，`swe_cron_result_index.trace_id`，`swe_html_preview_click_events.trace_id` | 用于关联执行记录、推荐结果和点击事件的链路标识，各表字段分别表示该记录所属的执行链路；不是任务编号或执行记录主键。执行表该字段允许为空且无唯一约束，不能假定一个标识只对应一行执行记录。 |
| 方案查看状态 | `swe_cron_executions.is_read` | 用于确定客户经理是否查看过对应的客户方案，1表示已查看。状态记录在执行记录上。 |
| 目标客户经理工号 | `swe_wealth_plan_targets.sap_id` | 规划分发对象的客户经理工号；与规划创建人或负责人区分。 |
| 客户经理工号 | `rm_jkh_user_info.user_id` | 客户经理基础信息中的工号，与目标客户经理工号关联以获取机构和等级；该字段本身不是单列唯一键。 |
| 结果类型 | `swe_cron_result_index.result_type` | 区分任务执行结果的类型；与记录客户UID的推荐客户标识是不同字段。 |
| 推荐客户标识 | `swe_cron_result_index.custuid` | 结果索引表记录名单任务和客户方案任务的执行结果，类型由结果类型字段区分，不能仅凭本字段是否为空判断。本字段记录对应客户的UID且不允许NULL；名单任务不记录客户UID，字段为空字符串，客户方案任务记录客户UID。 |
| 点击客户标识 | `swe_html_preview_click_events.customer_id` | 点击事件针对的客户UID；不是点击操作者的用户标识。 |
| 接触客户标识 | `swe_skill_contact_detail.cust_uid` | 接触明细对应的客户UID；与推荐客户标识、点击客户标识属于不同字段，允许NULL和空字符串。 |

## RULE_DATE 日期与执行

排程生成规则（用户于2026-11-12确认）：定时任务基于场景排程表达式，在T日生成T+1日的排程数据。排程表示计划安排，不代表实际已执行。

按排程执行日期筛选，含首尾日期；实际执行时间的日期部分匹配对应排程记录的排程执行日期，且实际执行时间不早于规划创建时间。每个任务在每个排程执行日期选择实际执行时间最新的执行记录，再按执行链路标识取记录，回查必须限定原任务、原排程日期且实际执行时间不早于规划创建时间；不额外以规划发布状态、规划有效期开始日期、规划有效期结束日期限制统计。没有执行记录不进入常规执行统计；有执行记录但没有成功推荐结果仍保留规划、技能及客户经理维度。

## RULE_SCOPE 机构与去重

统计机构来自目标客户经理：目标客户经理工号关联客户经理工号，分行取分行编号、支行取支行编号、等级取客户经理等级。规划负责人用于展示，不替代统计客户经理。编号是筛选和去重依据；机构使用分行编号与支行编号组合。区间、分行和各下钻维度分别重新去重，不能累加每日或子维度数值。

## RULE_RESULT 成功推荐结果

成功推荐结果：匹配当前统计范围内选定的执行记录和规划场景，且结果类型=plan、最新成功结果标记=1、结果状态=SUC的结果记录。

推荐结果记录的任务编号和执行链路标识分别匹配执行记录的任务编号和执行链路标识，推荐结果记录的技能编号匹配规划场景的技能编号。

## RULE_TASK 任务执行与成功推荐

业务口径：用户于2026-11-12确认。当前实现保留taskCount名称用于成功推荐客户方案数，并追加scheduledTaskCount、executedTaskCount、pendingTaskCount、failedTaskCount。

| 指标 | 统计规则 |
| --- | --- |
| 应执行任务数 | 在所选排程执行日期范围内，按目标客户经理工号、规划编号、技能编号、排程执行日期和任务编号确定应执行任务，包含没有执行记录的任务。 |
| 已执行任务数 | 应执行任务中，存在对应执行记录的任务数量；执行失败也属于已执行。同一应执行任务多次执行只计一次。 |
| 待执行任务数 | 应执行任务中，没有对应执行记录的任务数量；不拆分未来未到期与已到期未执行。 |
| 失败任务数 | 已执行任务按最新执行记录的status判定，仅success成功，其余均失败，不使用async_status。 |
| 成功推荐客户方案数 | 基于[成功推荐结果规则](#rule_result-成功推荐结果)，仅统计客户方案任务的结果记录，排除客户名单结果，按执行链路标识与推荐客户标识组合去重；一次任务产生多个客户方案时计多项。 |

应执行任务数＝已执行任务数＋待执行任务数。成功推荐客户方案数的计数单位是客户方案，与前三项任务数量不同，不要求小于或等于已执行任务数。不新增“成功推荐名单数”指标。

客户方案结果类型已确认为plan；成功推荐客户方案数排除空客户标识，按执行链路标识与客户标识去重。原taskCount的人均、户/任务及排序引用保留。应执行任务数＝已执行任务数＋待执行任务数，失败任务数是已执行任务数的子集。

## RULE_CUSTOMER 客户与行为

推荐客户数按非空推荐客户标识去重；方案被查看客户数按方案查看状态=1的执行记录对应的推荐客户标识去重。

去洞察客户和去电访客户对应的点击事件要求事件类型=button_click，分别按按钮类型=insight和按钮类型=phone区分。点击事件的执行链路标识匹配执行记录的执行链路标识，点击客户标识匹配推荐客户标识，点击时间与实际执行时间同日；去洞察客户数和去电访客户数分别按点击客户标识去重。点击不等于已接通或有效接触。

接触通过接触明细的点击事件编号匹配点击事件的点击事件编号关联点击事件，点击要求事件类型=button_click，或事件类型=preview_view 且模板类型=sub；点击事件的执行链路标识匹配执行记录的执行链路标识，点击客户标识匹配推荐客户标识，点击时间与实际执行时间同日。接触客户数按接触客户标识去重，忽略 NULL、保留空字符串。不额外要求接触客户标识等于推荐客户标识，不将接触率截断到100%。

## RULE_RATE 比率与机构基准

方案被查看率、洞察率、电访率、接触率均以推荐客户数为分母。数量无数据为0，分母为0时比率为null；百分比和百分点差值 HALF_UP 保留两位，人均整数，户/任务一位。比较和差值使用未舍入值，不能先舍入再相减。

机构基准保留排程执行日期范围和分行编号筛选条件，去掉支行编号、客户经理等级和技能编号筛选条件，以整体去重数据计算，不平均支行率。表格高低标识使用±3个百分点；需关注支行采用严格低于基准，两者不能混用。
