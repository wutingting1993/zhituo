# 通用知识面板接入计划

**目标**　在业务系统点击开发模式后，在当前页面打开统一部署的知识面板。沿用已确认的 iframe 方案。

**源码与发布**　首期在 PlanReport 仓库内新增独立构建入口，从现有报表工作台拆出通用面板。面板独立部署，随面板发布版本化的浏览器脚本 `/embed/v1/loader.js`。业务系统在全局布局引入脚本，在现有开发模式入口调用 `KnowledgePanel.open({ systemCode, page, componentId })`，其中 `componentId` 可选。PlanReport 首期沿用登记用的页面路径和现有组件注册表，页面路由与登记路径的映射可在知识侧维护。

**现有接入点**　PlanReport 的 `src/dev/DevTools/index.tsx` 在打开时挂载 `DevWorkbench`，入口已有 `knowledgePagePath`，没有直接接收当前组件 ID。`src/dev/DevWorkbench/index.tsx` 在工作台内处理组件选择，也读取宿主 DOM 的 `data-component-id`。Vite 的知识 API 代理只提供本地转发依据，生产部署和内嵌会话需要实测。

- [ ] **建立独立面板入口。** 在 PlanReport 仓库配置面板的独立构建，本地用两个端口验证宿主打开 iframe、加载脚本和传递上下文。面板通过自己的同源代理访问已有知识 API。
- [ ] **提取知识面板。** 以 `src/dev/DevWorkbench/ContractPanel` 及其知识读写逻辑为复用起点，核对 API、编辑与审核依赖。保留宿主 DOM 的定位能力在业务侧，由宿主传递系统标识、页面路径及可选组件 ID。确认明确组件、页面唯一匹配、多个匹配和无匹配分别得到合理结果。
- [ ] **接入开发模式入口。** 首个宿主从 `src/dev/DevTools/index.tsx` 接入通用加载器。加载器管理 iframe 开关和加载失败提示。面板就绪后接收页面上下文，双方校验消息来源与发送窗口。由知识服务校验对应系统、组件及读写操作的权限。以原入口验证打开、关闭及路由切换。
- [ ] **验证部署与会话。** 面板取得试点地址后，检查宿主来源配置、内嵌登录、未登录及无权限响应。确认鉴权链路后验证知识写入和审核。
- [ ] **登记分仓组件并验收第二个宿主。** 用一个实际组件关联前端和后端仓库、源码位置及版本信息。在两个业务域名通过开发模式打开同一套面板，验证知识读写、组件选择及两端定位，记录每个宿主的实际改动和无法复用的配置。
- [ ] **交付验证。** 执行改动项目适用的 lint、类型检查及构建。如果接口契约变化，同步修改接口文档。单元测试和 E2E 按项目授权执行。
