# 接口监控 Java 类型设计

## 目标和范围

将智拓后端接口监控的五个查询和离线刷新改为明确的 Java 对象。范围包括 Web 接口、应用服务、领域数据访问契约、ClickHouse 客户端及本地 Mock。沿用现有路径、统计口径和 ClickHouse SQL。

## 类型和边界

- 应用层为五个查询提供明确的响应类型，复用指标、列表项、覆盖区间、总览和榜单对象。维持现有响应信封、字段名、空数组和可空指标语义。
- 领域数据访问契约使用明确的查询条件、统计行、覆盖记录及刷新请求类型，统计和覆盖分别返回带元素类型的列表。应用服务按字段访问器组装响应及排行。
- ClickHouse 适配器用明确的协议类型序列化和反序列化现有字段，并在适配边界转换。计数、比率、时间和标识按现有协议类型读取。Mock 通过同一领域契约返回数据，保持目前的模拟口径。
- 刷新成功只表达操作成功，Web 入口使用 `Result<Void>`。ClickHouse 刷新的成功标识仍由适配器校验，失败沿用现有错误响应。前端当前只使用成功或失败状态。

## 方案比较

已选全链路类型化，能让编译器检查字段和列表元素类型，并使 Mock 与实际查询共用领域契约。另一可行方案是在 ClickHouse 适配器暂留 JSON 树，仅类型化应用和页面响应，改动面更小，但上游字段读取仍由字符串和运行时转换决定。

## 验证

对照现有五个查询的响应结构，核对 Mock 和 ClickHouse 的字段映射，以及空结果、未归属、缺失比率、空桶、Top 10 和刷新错误。执行 Java 静态检查、编译和架构检查，并使用本地 Mock 核对 HTTP 响应。真实 ClickHouse 联调依赖目标环境。
