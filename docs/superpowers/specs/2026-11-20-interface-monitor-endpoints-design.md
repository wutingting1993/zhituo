# 接口监控查询拆分

首页、接口详情和专家详情按业务用途调用独立的查询接口。一个版本内切换前端和后端，并删除原 `POST /api/v1/interface-monitor/query`。

## 接口

以下查询均为 POST，路径前缀为 `/api/v1/interface-monitor`。请求包含 `startDate` 和 `endDate`，响应沿用现有结果信封。

| 路径 | 业务筛选 | 响应 |
| --- | --- | --- |
| `/overview` | 日期范围 | 全局汇总及现有 Top 10 榜单 |
| `/interfaces` | 可选专家筛选 | 接口指标列表 |
| `/experts` | 可选接口筛选 | 专家指标列表 |
| `/summary` | 接口或专家筛选 | 详情指标汇总 |
| `/trend` | 接口或专家筛选 | 详情趋势和覆盖信息 |

后端按入口确定统计分组。趋势查询沿用现有页面规则，单日按 10 分钟聚合，多日按天聚合。各入口保留其现有的业务筛选语义，包括适用场景下的未归属专家筛选。前端请求移除 `groupBy` 和 `bucketSeconds`，所有查询调用和接口登记随契约更新。

页面布局、离线刷新、指标计算、ClickHouse 路径配置和本地 Mock 方式沿用现有实现。验证五个新入口的响应及首页、接口详情、专家详情的数据加载，并检查旧路径和旧请求字段已从前端调用中移除。

## 方案比较

已选方案按五种数据用途拆分。接口列表和专家列表可供首页及详情复用，汇总和趋势共享相同契约。按页面位置拆分可以给每个页面独立入口，但会为接口详情和专家详情维护多组相同结构的契约。
