# 专家批量请求完整周期监控

## 已确认的业务口径

统计两个 POST 入口，每个请求计一个批次。

- /api/engine/v1/rule-data/batch-query
- /api/engine/v1/rule-data/batch-query/details

专家抽屉中的批量请求汇总按专家和页面日期计算。内部配置接口表格继承专家、日期和页面接口筛选。两个区域通过专家关联，事件通过 batchId 关联。整批耗时独立统计。

批次结果分为全部成功、部分失败、失败和取消。所有查询项成功为全部成功，既有成功项也有失败项为部分失败，全部查询项失败或请求异常为失败。正常返回 HTTP 200 仍须检查查询项结果。只有全部成功计入成功 TPS。取消单列。

## 当前实现核对

BatchQueryController 将两个入口交给 BatchQueryService。BatchMonitorContext 通过 BATCH_RECEIVED 记录 batchId、专家、入口和原始请求。EXECUTION 和 UPSTREAM 的终态仅覆盖内部接口阶段。现有数据缺少批量响应完成事件。

Flink SQL 将 BATCH_RECEIVED 写入 interface_monitor_batch，将 EXECUTION 和 UPSTREAM 阶段写入 interface_monitor_event。智拓报表读取十分钟离线桶，现有秒级计数支持接口活跃 P95。上述数据无法完整还原批量响应周期。

## 采集设计

新增批量请求生命周期事件 BATCH_STARTED 和 BATCH_FINISHED。沿用同一批次的 batchId、agentId、traceId 和 entrypoint。

HTTP 层在两个入口开始处理时记录墙上时间和单调计时起点。完整耗时截止到服务端响应写出完成，覆盖业务执行、结果转换和响应序列化。通过 WebFlux 请求生命周期关联批次上下文，并保证错误、取消与正常完成最多发布一个终态。业务层只补充结果分类。

服务端无法据此测量调用方实际收完响应的时间。页面 Tooltip 明确为服务端接收请求至响应写出完成的耗时。

请求解析或校验失败时，专家可能无法可信确定，归入未归属请求。记录 HTTP 状态与失败结果，不把请求体重新解析失败当作专家身份依据。业务正常响应时按查询项结果判定结果，发生响应写出异常时覆盖为失败或取消。

保留既有 BATCH_RECEIVED 请求快照及内部接口事件，生命周期事件共用批次关联标识。

## 存储和离线统计

批次生命周期明细独立存储，保留阶段、时间、专家、入口、结果及耗时。使用事件唯一标识去重，并按原始事件时间划分日期。

新增分钟离线统计，维度为专家、入口和自然分钟。保存开始数、各结果完成数、耗时总和、耗时样本数、可合并耗时百分位状态及单秒开始计数。另保存明确的覆盖范围和统计完成时间。按闭合分钟发布，失败可重试，同一统计键重算替换。

开始次数按开始事件发生时间计算，完成数及耗时按完成事件发生时间计算。跨分钟、跨天请求可分别落入开始窗口和完成窗口。整段平均耗时使用总耗时除以样本数，整段 P95 合并耗时状态后计算。

有离线覆盖且无事件的分钟输出 0。尚未发布统计的分钟显示无数据。保留原始分钟数据，跨日期汇总时先合并计数。历史缺少批量终态的时段显示不可用，采集上线后开始积累完整指标。

现有接口活跃 P95 和峰值统计继续供内部接口列表使用。

## 查询和展示

专家抽屉增加独立的批量请求整体指标区域，注明按当前专家和日期统计。沿用现有请求客户端、错误提示和加载状态。内部接口表格保留既有数据来源。

汇总显示请求次数、完成次数、平均耗时、P95 耗时、全部成功数、部分失败数、失败数、取消数。无耗时样本时耗时为空。

分钟趋势使用相同的固定自然分钟窗口。

- QPS 为本分钟收到请求数除以 60。
- 完成 TPS 为本分钟成功、部分失败和失败的完成数之和除以 60。
- 成功 TPS 为本分钟全部成功数除以 60。
- 取消数单独展示，取消不计入完成 TPS 或成功 TPS。
- 部分失败率和失败率的分母为成功、部分失败和失败完成数之和，分母为 0 时为空。
- 平均耗时和 P95 耗时包含成功、部分失败和失败请求，取消不计入。

分别按两个入口展示或合并两个入口时，同一分钟计数先合并，再计算速率。分钟曲线与汇总明确标注统计完成时间，便于识别离线数据时效。

新增查询契约与现有内部接口统计隔离，返回批量汇总、分钟趋势和覆盖信息。请求只接受日期和专家条件，接口筛选由内部接口查询处理。

## 验证与交付

实现前读取各目标项目规范，保留已有工作区改动。同步更新引擎事件契约、Flink 映射、ClickHouse DDL、离线 SQL 和报表 API 文档。

必要检查包括修改文件的 Java 静态检查、目标项目编译与架构检查、前端格式与类型检查及构建。单元测试和 e2e 测试按项目要求另行取得授权。

核对全部成功、部分失败、全部失败、请求异常、取消、跨分钟和跨天请求、事件重发、零流量分钟及历史缺失终态。核对内部接口表格与批量汇总的专家和日期参数。迁移及外部链路发布按实际连接与授权执行，并明确报告未部署范围。

## 实施顺序

1. 引擎生命周期采集及事件契约。
2. Flink 入库规则和 ClickHouse 明细、分钟离线表与聚合。
3. 智拓批量指标查询和 API 文档。
4. 专家抽屉汇总与分钟趋势。
5. 静态检查、构建和已授权范围内的链路验证。

## 后续确认

用户取消查询项数量统计。采集事件、离线计算和页面均移除该指标。页面按请求规模、执行结果、响应耗时分组，部分失败及失败将次数和对应占比合并展示。已部署表的历史列保留以兼容既有数据，新的写入和查询不使用这些列。
