# 智拓报表接口需求

## 需求范围

仅开发检索条件和顶部六项统计指标的接口。包含卡片上的辅助说明，不包含前端、下方报表、下钻功能和数据库建表。

## 接口与检索条件

| 接口 | 用途 | 入参 | 返回内容 |
| --- | --- | --- | --- |
| `POST /api/v1/reports/filters` | 获取检索选项 | 分行编号、支行编号、技能编号列表，均可不传 | 分行、支行、技能及客户经理等级选项 |
| `POST /api/v1/reports/summary` | 获取顶部指标 | 开始日期、结束日期必填；分行编号、支行编号、等级、技能编号列表可选 | 六项指标及卡片辅助数据 |

两个接口均使用 JSON body 传参，不使用查询参数；技能列表为 JSON 数组。

检索规则：

- 统计日期指排程表 `swe_plan_sence_cron.execute_day`，按日期比较，包含开始日和结束日；开始日期不能晚于结束日期。全部指标及机构基准均使用此日期范围。
- 执行表 `swe_cron_executions.actual_time` 用于匹配排程当天的执行记录，并选择当天最新的一次执行，不作为独立的日期筛选口径。点击表的 `clicked_at` 用于匹配该次执行当天的客户行为。
- 分行、支行单选，技能多选；不选表示全部，多个技能之间为“或”。
- 分行、支行、技能相互联动：查询某一类选项时应用另外两类条件，不用该类自身的已选值限制候选项。日期不影响候选项。
- 分行与支行不匹配时返回参数错误。等级直接使用数据库中的实际等级值。
- 按编号筛选和去重，名称仅用于展示。

## 六项指标口径

各指标均使用所选日期、分行、支行、等级和技能范围内的数据，整个区间统一去重，不累加每日或各支行统计值。

| 指标 | 业务含义 | 技术口径 |
| --- | --- | --- |
| 规划数 | 所选日期内参与执行的规划总数 | 按规划编号 plan_id 去重。同一规划多次执行计1条；有执行记录但没有推荐客户的规划仍计入。不按当前发布状态和有效期筛选 |
| 技能数 | 所选范围参与执行的技能总数 | 按技能编号 skill_id 去重。同一技能被多人、多条规划或多天使用计1项；有执行记录但没有推荐客户的技能仍计入 |
| 任务数 | 所选日期内的名单任务与方案任务总数 | 在匹配成功的结果记录中统计，结果要求 result_type=plan、is_latest_success=1、status=SUC。custuid='' 表示名单任务，按执行编号 trace_id 去重；custuid!='' 表示方案任务，按“trace_id、custuid”组合去重。两类数量相加。未匹配到结果记录的执行不计入任务数 |
| 推荐客户数 | 所选日期内获得推荐的客户总数 | 数据取自 swe_cron_result_index.custuid，该字段不会为 NULL。仅统计非空字符串的客户标识，按 custuid 去重；同一客户跨日期、人员、技能只计1户 |
| 方案被查看率 | 推荐客户中方案已被查看的客户占比 | 找出执行记录查看标记 is_read=1 对应的推荐客户，按 custuid 去重，得到已查看客户数。查看率＝已查看客户数÷推荐客户数×100%。同一客户有一次符合条件的查看即计入；客户空值处理同推荐客户数 |
| 接触率 | 推荐客户中已接触客户的占比 | 通过执行当日的客户点击记录找到接触明细，按接触客户标识 cust_uid 去重。接触率＝已接触客户数÷推荐客户数×100%。NULL 不计，空字符串计为一个值；不额外要求 cust_uid 与推荐结果 custuid 相等，不将结果强制截断为100% |

数量无数据时返回0；率值返回数值百分比，四舍五入保留两位小数，推荐客户数为0时返回 null，页面展示“—”。

卡片辅助数据：

| 数据 | 技术口径 |
| --- | --- |
| 覆盖支行数 | 在相同统计范围内，按“分行编号、支行编号”组合去重计数 |
| 使用最多的技能及人数 | 每个技能按客户经理工号去重统计人数，取人数最多的技能；并列时按技能编号升序取第一项，无数据返回 null |
| 人均任务数、人均推荐客户数 | 对应数量÷客户经理人数，四舍五入为整数；客户经理人数按相同范围内的工号 sap_id 去重，人数为0时返回 null |
| 机构基准率 | 保留日期和分行条件，取消支行、等级、技能条件，重新计算整体查看率和接触率；未选分行时为全行。使用整体客户数计算，不平均各支行率值 |
| 较机构基准差值 | 当前率值－机构基准率值，单位为百分点；按未舍入值计算后保留两位小数。任一率无法计算时返回 null |

## 数据来源与匹配规则

统计数据需按人员、规划、技能、任务、执行结果和客户行为的关系匹配，具体规则如下。

| 步骤 | 获取什么 | 表与匹配规则 |
| --- | --- | --- |
| 1. 确定人员和机构 | 执行人员、分行、支行、等级 | 规划目标表 swe_wealth_plan_targets 的 sap_id 对应人员表 rm_jkh_user_info 的 user_id。分行取 first_bbk_id，支行取 org_id，等级取 pst_lvl |
| 2. 确定规划和技能 | 人员对应的规划及技能 | 规划表 swe_wealth_plans 的 id，对应目标表和场景表 swe_wealth_plan_scenes 的 plan_id；场景表 scene_id 对应技能表 swe_marketplace_skills 的 skill_id。规划、目标、场景均要求 deleted=0，技能要求 source_id=RMASSIST |
| 3. 找到任务和执行日 | 该人员执行该规划、该技能的任务 | 任务表 swe_cron_jobs 的 tenant_id、plan_id、skill_ids，分别匹配人员工号、规划编号、场景 scene_id；skill_ids 整字段相等匹配，不拆分。要求 source_id=RMASSIST 且 status不为deleted。排程表 swe_plan_sence_cron 的 plan_id、sence_id 匹配规划和技能，execute_day 落在所选日期内 |
| 4. 选择执行记录 | 每个任务每天最新的一次执行 | 执行表 swe_cron_executions 按 job_id 和执行日期匹配任务与排程，按 actual_time 倒序取第一条的 trace_id，再按 trace_id 获取执行记录；actual_time 必须不早于规划 created_at。同时间并列取其中一条，不额外限制 status、is_final。没有执行记录则不纳入指标 |
| 5. 获取推荐客户与查看状态 | 本次执行对应的客户及是否查看 | 结果表 swe_cron_result_index 同时匹配 job_id、skill_id、trace_id；要求 result_type=plan、is_latest_success=1、status=SUC，不额外限制 expire_at。客户取 custuid，查看标记取执行表 is_read。没有匹配结果仍保留规划、技能和执行信息 |
| 6. 获取接触客户 | 通过客户点击找到接触记录 | 点击表 swe_html_preview_click_events 同时匹配 trace_id 和推荐客户标识 customer_id，clicked_at 与执行 actual_time 为同一天；事件要求 event_type=button_click，或 event_type=preview_view 且 template_type=sub。点击表 id 对应接触表 swe_skill_contact_detail 的 click_id，接触客户取 cust_uid；不额外限制接触时间和按钮类型 |

检索候选项使用步骤1—3的关系，不要求已有执行结果；统计指标使用全部步骤。匹配产生的重复记录按各指标指定的编号去重，不按名称去重。

## 验收要求

- 仅提供检索条件和顶部六项指标及其辅助数据，不包含下方报表或下钻功能。
- 分行、支行和技能按联动规则返回候选项；候选项不受统计日期限制。
- 统计日期使用 execute_day，包含开始日和结束日；机构基准使用相同日期范围。
- 各项数量在整个筛选范围内按规定去重，同一对象跨日、跨人员或跨技能不重复累计。
- 任务数包含名单任务和方案任务；推荐客户数仅统计 custuid 不为空字符串的客户。
- 无数据时数量返回0；比率及人均值的分母为0时返回 null。
- 率值保留两位小数，人均值四舍五入为整数，基准差值使用百分点。
- 开始日期晚于结束日期、分行与支行不匹配时，返回可理解的参数错误说明。
