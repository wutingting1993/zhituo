# 智拓报表接口需求：规划视角—分支行规划覆盖

## 需求范围

本文定义分支行规划覆盖表及规划明细的后端接口需求，不包含前端或数据库建表。不包含右侧来源结构、规划洞察和导出。

本模块与现有存量统计接口（当前项目为顶部统计 `POST /api/v1/reports/summary`）使用一致的基础数据范围与检索条件，增加分行、支行维度聚合及规划来源分类；按用户确认，仅统计三类指定来源，排除其他来源。用户确认的统计口径优先于 HTML 原型中的模拟逻辑。

## 日期口径与后续调整备注

当前版本统一使用顶部所选日期区间，包括“生效中规划”“今日任务”、覆盖客户及其他辅助统计，具体匹配和去重规则见下文。“今日任务”暂不限定为系统当天；“生效中规划”沿用存量统计判断，不额外增加当前发布状态或有效期限制。

备注：“今日任务”和“生效中规划”的日期及生效判定口径后期可能调整。当前按本文区间口径开发和验收，后续须在业务明确新规则后再修改，不提前增加切换配置或兼容逻辑。

## 接口与检索条件

下列接口均使用 POST 和 JSON body，实际参数及响应见 [接口说明](report-api.md)。

| 接口 | 用途 | 入参 | 返回内容 |
| --- | --- | --- | --- |
| `/api/v1/reports/plan-coverage` | 分支行规划覆盖 | 开始、结束日期必填；分行编号、支行编号、等级、技能编号列表可选 | 分行及下属支行、三类来源规划数、规划总数、支行数量 |
| `/api/v1/reports/plan-coverage/details` | 点击机构的规划明细 | 顶部检索条件、点击机构编号；来源可选，默认全部 | 机构信息、汇总数据、来源数量及规划列表 |

- 参数沿用现有接口的 `startDate`、`endDate`、`bbkId`、`orgId`、`level`、`skillIds`。技能多选，多个技能之间为“或”，其余单选；未选表示全部。
- 日期使用排程 `swe_plan_sence_cron.execute_day`，包含开始日和结束日；开始日期不得晚于结束日期。
- 机构、等级沿用存量接口：规划目标人员 `sap_id` 关联人员表 `user_id`，取 `first_bbk_id`、`org_id`、`pst_lvl`。按编号筛选和去重。
- 规划负责人是规划本身的负责人，与分发目标人员区分；负责人取主表创建人 `sap_id/creator_name`，用于明细展示，不能擅自改为按负责人的机构与等级过滤，否则会改变存量接口数据范围。
- 检索选项复用现有 filters 接口及联动规则。明细继承顶部全部条件，再限定点击机构；分支行不匹配或点击机构超出筛选范围时返回参数错误。

## 覆盖指标口径

| 指标 | 业务含义 | 技术口径 |
| --- | --- | --- |
| 我的关注 | 对应来源的规划数 | 当前机构范围内按规划编号去重，来源取规划主表 `source_label` |
| 分行关注 | 对应来源的规划数 | 同上，`source_label` 为“分行中台”，返回及展示名称为“分行关注” |
| 行长关注 | 对应来源的规划数 | 同上，来源为“行长关注” |
| 生效中规划 | 与存量统计一致的规划数 | 沿用 summary 的基础记录范围，仅保留三类指定来源后按 `plan_id` 去重；不另加发布状态、当前日期或有效期条件 |
| 支行数量 | 分行范围内覆盖的支行数 | 沿用存量接口覆盖支行口径，按符合条件记录的“分行编号、支行编号”组合去重 |

- 来源仅统计 `source_label` 为“我的关注”“分行中台”“行长关注”的规划；其中“分行中台”映射为页面“分行关注”。NULL、空字符串及其他来源不统计。该来源限制统一应用于覆盖表、支行数量、明细及辅助汇总。三类来源互斥，来源数量之和等于规划总数。
- 用户已明确“生效中与存量判断一致”。现有存量接口统计所选日期内参与执行的规划，不按当前发布状态及有效期筛选；此处沿用，不将 `status=published` 或 `period_start/period_end` 作为额外条件。
- 同一规划跨日期、技能或人员在同一机构内只计1条。规划可以被分发给多个支行，各支行分别去重；分行必须重新按规划编号去重，不能将支行数量相加作为分行规划数。
- 无数据数量返回0；无符合范围的机构返回空列表。原型展示全部零规划机构的行为不作为新增机构范围的依据。
- 按分行→支行两级展示，支持展开、收起；展开状态不影响数值。只有规划总数大于0时可下钻，来源列不提供下钻。
- 不新增排序、分页、跨机构总计等原型未要求的能力。

## 规划明细及辅助数据

| 数据 | 口径 |
| --- | --- |
| 标题 | 点击机构名称＋“生效中规划” |
| 来源筛选 | 全部、我的关注、分行关注、行长关注；仅过滤明细列表，重新打开默认全部 |
| 来源数量 | 点击机构在顶部条件下、未应用明细来源标签前的各来源规划数 |
| 生效中规划汇总 | 按规划编号去重，与覆盖表点击值一致 |
| 覆盖客户汇总 | 用户确认即推荐客户数；沿用存量口径，在整个点击机构范围内按非空字符串 `custuid` 去重，不累加各规划客户数 |
| 今日任务汇总 | 用户确认沿用现有任务定义，并应用顶部日期区间；名单任务按 `trace_id` 去重，方案任务按 `(trace_id,custuid)` 去重，两类相加。原型“今日任务”文案不代表额外限制为系统当天 |
| 关联技能汇总 | 同一机构和顶部条件下按技能编号去重，与存量技能数口径一致 |
| 列表字段 | 规划编号、名称、来源、关联技能、规划负责人姓名及等级、有效期、覆盖客户数、任务数 |

关联技能仅展示当前技能筛选范围内、且符合统计条件的技能，不展示该规划的其他关联技能。

列表按规划编号去重，各规划客户数、任务数在该规划及当前机构、顶部检索范围内计算。顶部四项汇总和来源数量不随抽屉来源标签切换重算。客户跨规划可能重复，汇总需整体去重，不能直接求和。无结果列表返回空数组，数量返回0。

## 数据来源与匹配规则

沿用 [智拓报表接口需求](report-api-requirements.md) 的完整匹配规则，不独立定义另一套执行统计逻辑。

| 步骤 | 表及规则 |
| --- | --- |
| 人员与机构 | `swe_wealth_plan_targets.sap_id = rm_jkh_user_info.user_id`；分行取 `first_bbk_id`，支行取 `org_id`，等级取 `pst_lvl` |
| 规划与技能 | `swe_wealth_plans.id` 关联目标及场景 `plan_id`；`swe_wealth_plan_scenes.scene_id = swe_marketplace_skills.skill_id`。规划、目标、场景要求 `deleted=0`，技能要求 `source_id=RMASSIST` |
| 任务与排程 | 任务的 `tenant_id`、`plan_id`、`skill_ids` 分别匹配人员、规划、技能；技能整字段相等匹配。任务要求 `source_id=RMASSIST`、`status!=deleted`；排程日期落在顶部区间内 |
| 执行 | 每任务每天按 `actual_time` 倒序取最新一次执行，且不早于规划 `created_at`；没有执行记录不计入。并列及状态处理与存量接口一致 |
| 结果 | 同时匹配 `job_id`、`skill_id`、`trace_id`，要求 `result_type=plan`、`is_latest_success=1`、`status=SUC`；无结果仍保留规划和技能，不计任务及推荐客户 |
| 来源 | `swe_wealth_plans.source_label`；严格匹配“我的关注/分行中台/行长关注”，其中“分行中台”返回及展示为“分行关注”；明细来源筛选“分行关注”对应数据库值“分行中台”。空值及其他来源排除。`source_id` 是入口来源，不能用于三类关注来源分类 |
| 规划展示 | 名称取 `swe_wealth_plans.name`，有效期取 `period_start/period_end`，仅展示，不增加筛选条件 |
| 负责人 | 用户确认负责人就是创建人：工号取主表 `sap_id`，姓名取 `creator_name`，负责人等级通过该工号关联 `rm_jkh_user_info.user_id` 后取 `pst_lvl`；不使用分发目标的 `target_name` 替代 |


## 验收要求

- 相同顶部条件下，模块沿用存量接口的基础数据范围、日期口径、执行匹配及去重规则，并统一排除三类指定来源以外的记录，不额外施加当前发布状态或有效期限制。
- 分行与支行均按规划编号去重；分行不累加支行规划数。跨支行规划在分行仅计1条。
- 来源按主表 `source_label` 的“我的关注/分行中台/行长关注”分类，来源合计等于总数；“分行中台”统一映射为“分行关注”，空值及其他来源不进入任何统计或明细。
- 覆盖表下钻保留全部顶部条件及点击机构，明细规划数与点击值一致；负责人展示不改变机构统计归属。
- 覆盖客户等于同范围推荐客户去重数；任务沿用名单任务与方案任务定义，并使用顶部区间。
- 来源切换只改变列表，汇总及来源数量保持不变；无数据返回0及空列表。
- 参数错误规则复用存量接口。接口参数及响应字段按接口说明验收。
